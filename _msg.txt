Add the unattended path

Four of the five steps already ran unattended; only the briefing needed a
model. That step now exists, and so does the plumbing to run it without a
laptop.

- brief_ai.py -- sends the spec and the extracted text to an OpenAI-
  compatible endpoint and writes the JSON the build already consumes.
  The shape is read out of PROMPT.md so the two cannot drift.
- daily.py -- the whole chain: extract, brief, build, commit, push. The
  only pluggable step is the brief, so the same script runs locally, in
  CI, or on a laptop.
- telegram_bot.py -- receives the PDF, commits it to incoming/, which is
  what triggers the workflow. Stdlib only.
- .github/workflows/daily.yml -- fires on a push to incoming/, builds, and
  publishes.
- SETUP-AUTOMATION.md -- the secrets and the bot.

PROMPT.md travels as a base64 secret rather than being committed. It is
gitignored because it names an employer, a client account and career
goals, and the repo is public; committing it to make Actions work would
have undone that. The workflow restores it and checks it looks like the
real spec before spending a model call on it.

The model response is not trusted. extract_json handles fences and leading
prose, the lints run before the file is written rather than after, and a
brief that fails either is never saved -- so a bad model response fails
at the source instead of surfacing later as a confusing build error.

Two tests for the new code, both proven to fire rather than just to pass:
test_brief_ai.py feeds fenced, prose-wrapped and truncated output through
the parser; test_workflow.js asserts the workflow still has the steps and
secrets it claims to, because a malformed workflow otherwise fails hours
later as a red X in a tab.

Not verified: no model has been called. brief_ai.py --dry-run reports the
size honestly (57k input tokens for the 19 Oct issue) and a real run needs
a key. Until one has run end to end, treat the brief step as unproven --
which is what SETUP-AUTOMATION.md tells them to rehearse first.
